# Growth Mission · live game

Групповая игра по онбордингу АБ-платформы 2.3. Две роли: ведущий и участник. 14 раундов / 5 актов, 75–90 минут обсуждения плюс реальные внешние действия по готовности.

## Для Zoom

1. Ведущий создаёт комнату и копирует приглашение. Участники входят по коду и имени без аккаунта.
2. До старта можно задать общую вводную. Новых участников можно допускать или закрывать вход.
3. Открыть раунд → индивидуальные решения → закрыть ответы → открыть разбор → следующий раунд. При таймере приём закрывается сервером; разбор открывает ведущий.
4. Ведущий видит сохранённые черновики, отправленные решения, уверенность и блокеры. «Экран Zoom» скрывает черновики и шпаргалку от демонстрации.
5. Письменные и практические решения оценить вручную 0–10 по трём критериям; добавить обратную связь. Вопросы с выбором оцениваются сервером, без бонуса за скорость. Очки не удостоверяют выполнение рабочего действия.
6. На финише CSV/JSON: участники, каждый раунд, ответы, выборы, уверенность, баллы, комментарии и ссылки/коды артефактов. Неотправленное остаётся черновиком, непройденное — непройденным; ожидающие ручной оценки обозначены отдельно.

## Реальная практика

Один общий эксперимент с дежурными ролями, а не десять конфликтующих запусков. Подготовить доступы, белый список/команду тестирования, готовые непересекающиеся .txt уведомлённых сотрудников с Android, рабочую ссылку и согласования. Выкат/модерацию при необходимости вынести между встречами. Ведущий отдельно фиксирует командный артефакт и ручное подтверждение.

Игра не подключается к банковской платформе, не получает КУСы и не проверяет фактический выкат. Синтетические данные анализа не получены из действий сотрудников. Внутренние скриншоты/логи остаются в рабочих системах. Полный самостоятельный маршрут: https://yakovlyskov.github.io/github.io/growth-lab/

## Данные и доступ

Общее состояние хранится в D1, синхронизация браузеров — опрос каждые 2 секунды при доступной сети. Состояние не зависит от вкладки ведущего. Статус «Пишет» означает недавнее сохранение черновика; присутствие оценивается по последнему запросу.

Код позволяет присоединиться, но не даёт прав ведущего. Ключи роли — случайные 256-битные значения, на сервере только SHA-256. Ключ-ссылка восстановления хранит секрет во фрагменте URL и очищается после входа. Ключ ведущего хранить отдельно от приглашения; личный ключ участника восстанавливает его место. На том же устройстве доступны сохранённые комнаты.

Правильные ответы, разбор и оценки не передаются участнику до открытия разбора; ответы других игроков не передаются ему. Ведущий видит черновики — об этом написано в интерфейсе. Публичный вход в приложение не означает публичный список комнат или доступ к их ответам без ключа. Максимум 40 игроков в комнате; интерфейс рассчитан на 6–15.

## Технологии

Vinext/React, Cloudflare Workers + D1. Конфигурация Sites — `.openai/hosting.json`. Миграции Drizzle schema-only, никаких CREATE/ALTER при HTTP-запросах. Учебная колода сохраняется в комнате, поэтому редакция контента не меняет начатую игру. Управление защищено ревизией и атомарным D1 batch с уникальной меткой операции.

`lib/deck.ts` — содержание, API — `app/api/game/route.ts`, UI — `app/game-client.tsx`, стиль — `app/game.css`.

## Проверка

`node scripts/test-game.cjs` исполняет реальные обработчики с SQLite/D1-адаптером: 10 участников, все 14 раундов, 139 отправленных решений и один намеренный пропуск. Проверяет черновики, сокрытие ключей/баллов, запрет позднего ответа, конкурентные команды ведущего, однократное продление, ручные оценки, контекст, истечение времени и экспорт.

Также: TypeScript, сборка, браузерные вкладки ведущего/участника, реальная локальная D1. Это не нагрузочный тест 10 браузеров и не проверка банковской платформы. Развёртывание через Sites сохраняет миграции и исходники; для локального запуска следовать инструкции включённого starter README / Sites workflow.
