# Первый эксперимент · Growth Lab 2

Интерактивный урок для команды АБ-платформы. Основание процесса — [инструкция заказчика 2.3 от 23.10.2026](https://docs.google.com/document/d/1F-udK7dMbjDO7lCcZXdV384FEN7NlGP-18EptZSvYLY/edit?tab=t.0), включая отдельный разбор незакрытых замечаний рецензентов. Исходный документ не изменяется.

Один HTML без зависимостей, сервера, внешних шрифтов и аналитики. Публикация: `growth-lab/index.html` в GitHub Pages. Ответы не отправляются в GitHub или банковские системы.

## Маршрут

29 шагов: бизнес-задача → гипотеза → реальные ограничения виджетов → метрики и план → доступы → Jira → согласования → онбординг и тестовый экран → поля/лимиты → расписание и белый список → аудитория и пересечения → варианты/диплинки → сохранение/проверка → тестовый экран → клиентская БЗРБ/CX → модерация → фактический выкат → отключение участника → завершение → анализ → роль аналитика → внедрение → ретроспектива → открытые вопросы.

Восемь внешних заданий подтверждаются участником вручную ссылкой/кодом и отметками. Урок не проверяет действия через API, сам не создаёт Jira, не выдаёт доступы, не загружает файлы и не запускает тесты в банке.

## Подготовка ведущего

Две встречи с паузой на доступы, материалы, согласования и выкат. Не обещать прохождение модерации в пределах одной сессии.

Подготовить доступы участников, белый список и команду тестирования, уведомлённых сотрудников с Android, готовые непересекающиеся `.txt` от аналитика, рабочий диплинк и короткое расписание. Основной кейс использует виджет-кнопку: лендинг и новая картинка не нужны. Реальные денежные операции не требуются.

Реальный запуск — в боевом АМ на Главном экране, без клиентской аудитории. Это не отдельная тестовая среда. КУСы, логи и банковские скриншоты остаются в рабочих системах.

Синтетический план 10 000 на вариант / 14 + 7 дней отделён от малого технического запуска. Фиксированные результаты не получены из действий сотрудников. Названия событий в выгрузке — предлагаемая учебная схема, не встроенный API платформы.

## Материалы и прогресс

Markdown: паспорт, Jira, поля платформы, ТЗ, аудитория, маршрут, корнер-кейсы, отчёт, ретроспектива, весь кейс. JSON: события и перенос прогресса. HTML A/B — иллюстрации кнопок без операций и аналитики. Неподтверждённый `.txt` не генерируется.

«С платформой» требует ручных подтверждений. «Обзор» допускает пропуск внешних действий. Свободная навигация в настройках обзора не засчитывает этапы и не создаёт ложное завершение онбординга.

Прогресс в localStorage этого браузера; JSON переносит его. Общей базы ответов нет. Ответы v1 сохраняются при миграции и в резервном поле JSON. После изменения маршрута этапы и подтверждения сбрасываются, чтобы не приписывать новые выполненные действия.

## Неутверждённые детали

Q3: назначение аналитика. Q4: формат/название файла, пример и фиксация онбординга. Q6: место фиксации согласования рисков при уже добавленной редполитике. Q7: статистика/эскалация/сроки жалоб при описанном отключении участника. Q1: временный Confluence до новой формы.

Комментарии о `client_pin` в столбик, переименовании полей, новом калькуляторе, результатах и вложениях — обсуждение, а не выпущенные функции. Рабочие ссылки и актуальные контакты открываются из оригинала.

## Проверка

Проверена синтаксическая корректность JavaScript. Проверка маршрута исполняет 29 рендеров, 28 переходов, 8 внешних подтверждений, неверный ответ, лимит поля, миграцию v1, экспортные документы и переключение режима.

Browser QA: старт, свободный просмотр, счётчик 500 символов, ошибочная БЗРБ, поиск участника по вариантам, сохранение. Публикация и выгрузки дополнительно проверяются на GitHub Pages. Реальная банковская платформа в QA не использовалась; мобильный viewport отдельно не проверялся.
