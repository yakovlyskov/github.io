# Первый эксперимент · Growth Lab

Самостоятельный интерактивный урок для команды платформы экспериментов. Один HTML-файл, без зависимостей, сервера, внешних шрифтов, аналитики и API.

Открыть `dist/index.html` в браузере или опубликовать как `growth-lab/index.html` на GitHub Pages. Настройка платформы и ссылка на эксперимент задаются самим участником. Страница не подключается к банковским системам и не подтверждает выполнение внешних действий автоматически.

## Сценарий

15 шагов: вводные → цель → гипотеза → варианты → аудитория → метрики → дизайн → черновик на платформе → проверка → запуск → промежуточные данные → финальные данные → решение → ретроспектива → итог.

Письменные ответы проверяются участником по критериям. В закрытых вопросах есть автоматическая проверка и объяснения. Эталоны не означают, что свободный ответ проверен моделью.

Прогресс сохраняется только в localStorage этого браузера. JSON позволяет перенести его на другой компьютер; Markdown служит отчётом, но не восстанавливает прогресс. Нет общей базы ответов или кабинета ведущего. Очистка данных браузера удаляет локальный прогресс.

Режим «С платформой» требует ручных подтверждений выполнения внешних заданий и ссылок/кодов артефактов. Режим «Обзор» позволяет изучить содержание без запуска; итог помечает внешние задания как неподтверждённые.

Все числа, персонажи, отзывы и результаты вымышлены. Финальные результаты не рассчитываются из фактического учебного запуска. При реальном запуске нужны заранее подготовленные тестовые страницы, сегмент сотрудников/тестовых учётных записей и обычный процесс согласования организации.

## Подготовка ведущего

1. Выделить 2,5–3 часа, подготовить доступы к платформе, учебный сегмент и маршрут согласования.
2. Назначить человека, который по ТЗ вернёт ссылки на страницы. Урок также генерирует HTML-заготовки A/B: они демонстрируют клики и не выполняют банковских операций. Подключение боевых событий и размещение страниц выполняются вашим процессом.
3. Назначить аналитика или дать готовый учебный план: минимум 10 000 на группу, 14 дней набора + 7 дней наблюдения. Для двух независимых долей при baseline 5%, MDE +1 п. п., alpha 5% (двусторонняя проверка), мощности 80% нормальная аппроксимация даёт около 8 200 человек на группу; 10 000 — учебное округление с запасом, а не универсальное правило.
4. Менять исполнителя за компьютером между этапами; записывать наблюдения, не объяснять заранее каждую кнопку.
5. На финише обсудить три затруднения и выбрать одно улучшение. Не каждую проблему требуется решать новой функцией.

## Проверка

Ручное browser QA через Sites preview: последовательность шагов, обратная связь, блокировка пропусков, сохранение, внешний маршрут, экспорт/импорт, мобильная вёрстка. Никаких секретов и персональных данных для прохождения не требуется.
